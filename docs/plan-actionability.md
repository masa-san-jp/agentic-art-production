# Production method and content qualification

AAK-10 implements pinned AAK specification/plan `b0e7c7f8d0a1f756fa708deef4fb380a62e45e0d`. Production owns both the method schema and its assessment. Research still owns the accepted immutable handoff; this extension does not edit that bundle or infer that proposed methods are measured facts.

After `new_production`, the external agent writes `02_specification/production-method.yaml` in the external production project using `schemas/production-method.schema.json`. The handoff hash binds it to the accepted research. The agent supplies a proposed method from the actual handoff, chosen medium and known environment: specification values or reasoned non-applicability, task IDs already derived by Production, instructions, actor, conditions, native material/resource IDs, requirement/specification coverage and observable completion checks. Every step is `NOT_RUN`. Unknown values retain an explicit check method, actor and condition. Required unknown specifications prevent readiness. The existing budget/calendar gaps also require explicit resolution plans; a resolution plan is not a successful measurement or quotation.

```bash
.venv/bin/python tools/build_plan.py --project-root /absolute/external/project
.venv/bin/python tools/plan_actionability.py --project-root /absolute/external/project
```

The builder includes the method and `plan-actionability/v1` assessment in the canonical aggregate and its existing integrated Markdown renderer. Content `PLAN_READY` is separate from `PLANNING`, execution readiness and human approval. The assessment grants no external effects. Missing mandatory procedures, broken references, native blocking content gaps and environment mismatches block content readiness. Existing visual asset validation checks actual files, hashes and conceptual/simulated provenance. The qualification CLI also checks the exact rendered bytes; a successful builder exit alone is insufficient.

`config/plan-actionability.yaml` defines physical, digital and hybrid required specification categories. Non-applicability requires a reason and cannot simultaneously be cited as an applicable step specification. Each production step connects to the accepted task's requirement IDs and retains required native inputs. The first production action, actor, materials/resources and start conditions appear directly in the integrated plan. Reference conditions for reused materials, steps, resources, budget or schedule must match the declared target environment. Knowledge and code commits remain separate. These are source declarations, not cryptographic proof that a source is true; AAK-11 supplies immutable owner knowledge retrieval. No prose classifier claims to prove physical feasibility or detect every semantic contradiction.

Compatibility: legacy aggregates without a method remain readable with unchanged outputs and lifecycle behavior, but the new qualification CLI reports `INCOMPLETE`. No migration modifies existing projects or handoff schemas. The additive `production-method/v1` and `plan-actionability/v1` fields are schema-validated and covered by aggregate integrity. A method input change requires regeneration and a fresh public review if publication is intended. Production #60's canonical public attestation remains the sole publication/body contract; its review and approval gates are unchanged. Private content qualification does not itself require publication consent.

Validation: `tests.test_plan_actionability` exercises distinct minimal/digital and task-matrix/physical handoffs, explicit first-action rubric, missing specifications and procedures, inconsistent task inputs, unsupported execution status, qualified gaps, incompatible reuse conditions, damaged visual files and URLs, forged content readiness, byte-for-byte rendering, and the real #60 attestation. Fixtures are synthetic proposals, not actual production, purchases, installations or live-agent acceptance evidence.
