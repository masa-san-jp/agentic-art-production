# Observation migration

`OBSERVATION_RECORDED` is the v1 append-only observation event. The canonical source is the shared `05_execution/production-log.jsonl`; `05_execution/observations.yaml` is regenerated by replay and must not be edited.

The previous result builder generated `OB001` from lifecycle state. That synthetic fallback is removed. Existing projects may therefore produce `observations: []` until an explicit observation record is appended. No lifecycle state, project ID, or observation text is inferred during migration.

To migrate an existing Git-external project:

1. Initialize or restore the complete execution log and every projection with `tools/run_execution.py ... init`; a partial execution state is rejected.
2. Create one metadata-only JSON record per actual observation using `observation-record.schema.json`. Keep `statement`, `method`, and `limitations` unchanged; do not add asset bodies or private source material.
3. Append each record with an explicit `--occurred-at`, actor, and idempotency key using `record-observation`.
4. Run `replay`, project validation, and result generation. The result contains only the latest `ACTIVE` revision; `RETRACTED` revisions remain in the append-only history.

No old result file is rewritten in place. If an existing result ID was already exported, generate a new result ID when the observation set changes.
